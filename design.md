# Universal graphic-design operating standard

This document defines the designer's method. A client's visual identity belongs in its own brand package. The core has no house palette, mandatory logo, bilingual format, industry or poster style.

## Start from the communication job

Understand who should see the work, what they need to understand or do, where it will appear, and which content and assets are authoritative. Choose the format and information hierarchy from that job. Ask for missing information only when it materially affects the result.

## Establish the brand context

Use an existing approved guide first. If deriving a system from public material, inspect actual publications and record what was visible, their dates and direct sources. Separate recurring design families from one-off campaigns. Document inaccessible channels and missing originals instead of extrapolating.

Classify each rule as **official**, **observed**, **inferred** or **proposed**. Classify each asset as **source original**, **source adaptation**, **redrawn** or **new original work**. An archived screenshot cannot establish an exact typeface, colour standard or master logo.

## Keep these concerns separate

| Concern | Brand-package responsibility |
| --- | --- |
| Identity | Original marks, variants, placement rules, clear space and actual source resolution |
| Colour | Approved tokens or explicitly provisional samples; role and contrast |
| Typography | Font families, licences, weights, language coverage and information hierarchy |
| Composition | Grid, spacing, panels, image treatment and optional motifs |
| Content | Field names, mandatory facts, copy, language variants, CTA and notices |
| Publication | Template, aspect ratio, sequence, delivery format and platform preview |
| Workflow | Sources, review owners, update triggers, versions and delivery checklist |

Keep working layers independent. A finished export can be flattened; the master should retain usable text and components. Preserve source logos and their proportions. Transparent placement assets must contain actual transparency, not a checkerboard screenshot. Use original scalable artwork when available; never label a raster embedded in SVG as a vector logo.

## Choose an appropriate production route

The included renderer handles text, geometric shapes and local image/vector assets in brand-defined static compositions. Templates and content fields are data, so a new industry does not require a new engine. Its output is editable SVG plus PNG.

For photographic editing, illustration, complex documents, motion or specialist print preparation, use an appropriate available tool and follow the same brand/evidence discipline. Do not imply that one static template engine automates every design discipline.

## Adapt rather than blindly resize

A square, portrait and landscape placement may need different hierarchy, crop and text length. Treat these as distinct templates when needed. Text length, required font coverage and actual preview conditions matter more than arbitrary universal point sizes. Do not invent platform limits, safe zones or print settings.

## Review before delivery

Check hierarchy, legibility, spelling, translation, claims, dates/prices where relevant, cropping, colour contrast, logo quality, transparent edges and the smallest text at the intended viewing size. Validate every slide in a sequence. Mechanical validation assists review; it does not replace visual and factual judgement.

Deliver the editable master, requested exports, provenance and version information. Captions and alt text are drafts unless verified. Generation alone does not authorize publication or distribution of client files.

## Maintain the system

Keep reusable behaviour in the core and client-specific rules under `brands/<id>/`. Introduce a new template only when the communication job needs it. Record source changes and retain old job versions. A change to a key fact should trigger review of all related language and format variants.
